# C++じゃんけんで学ぶオブジェクト指向

同じじゃんけんゲームを、次の2つの設計で実装した学習用プロジェクトです。

- **オブジェクト指向版**：具体的な振る舞いを各オブジェクトに任せる
- **手続き型中心版**：呼び出す処理と順番を `main()` が明示的に決める

実行結果はほぼ同じですが、コードの責務と差し替え方が異なります。2つを見比べることで、「クラスを使うこと」だけではなく、**オブジェクトに共通の役割を与え、具体的な処理をオブジェクト自身に任せること**を理解するのが目的です。

どちらか一方が常に優れていると考えるのではなく、変更が発生したときの修正箇所と、責務をどこへ置いているかに注目してください。

## 対象者

- C++のクラスや継承を学び始めた学生
- 継承、仮想関数、オーバーライドを実際のコードで確認したい人
- 「クラスを使えばOOPなのか？」という疑問を持っている人
- 手続き型とオブジェクト指向の設計上の違いを比較したい人

## 2つのプロジェクト

| プロジェクト | 設計 | 処理を選ぶ場所 |
|---|---|---|
| `Rock-paper-scissors` | オブジェクト指向版 | `Player` / `Enemy` の各オブジェクト |
| `Rock-paper-scissors-Procedural` | 手続き型中心版 | 主に `main()` と通常関数 |

### オブジェクト指向版

`Player` と `Enemy` を共通の `Actor*` として配列に入れ、同じ `Update()` を呼び出します。

```cpp
Actor* actors[2] = { new Player(), new Enemy() };

for (int i = 0; i < 2; i++)
{
    actors[i]->Update();
}
```

呼び出す側は、実体が `Player` か `Enemy` かを判定しません。`Actor::Update()` から純粋仮想関数 `SelectHand()` が呼ばれ、実体に応じて次の処理へ自動的に切り替わります。

- `Player::SelectHand()`：キーボード入力で手を選ぶ
- `Enemy::SelectHand()`：乱数で手を選ぶ

このため、`Actor` を継承した別のクラスへ生成部分を差し替えても、ゲームループは同じ形で利用できます。これは、この教材で特に注目する**抽象化と動的ポリモーフィズム**の例です。

ここで `Update()` 自体は仮想関数ではありません。常に共通の `Actor::Update()` が実行され、その内部にある仮想関数 `SelectHand()` だけが実体に応じて切り替わります。また、異なるオブジェクトを `Actor*` に格納しただけで動的ポリモーフィズムになるわけではありません。**基底型を通して仮想関数を呼ぶこと**で、実体に応じた処理の切り替えが働きます。

### 手続き型中心版

こちらも比較しやすいように `Actor`、`Player`、`Enemy` というクラスを使っています。ただし、手の選び方はオブジェクトの仮想関数ではなく、外側の通常関数として用意されています。

```cpp
Actor* player = new Player();
Actor* enemy = new Enemy();

SelectPlayerHand(*player);
SelectEnemyHand(*enemy);
```

変数の型がどちらも `Actor*` であっても、呼び出す側が正しい関数を選ばなければなりません。生成する型だけを差し替えても、呼び出す関数を変更しない限り、手の選び方は変わりません。

この版はクラス、継承、カプセル化を利用しているため、厳密な意味での「純粋な手続き型」ではありません。**クラスを利用しながら、ゲーム進行は手続き型を中心に組み立てたハイブリッド構成**です。これにより、「クラスや継承を使っただけで、自動的にOOPらしい差し替えが実現するわけではない」ことを比較できます。

## 比較するときの注目点

| 注目点 | オブジェクト指向版 | 手続き型中心版 |
|---|---|---|
| 手の選択 | 共通の `Update()` を呼ぶ | 専用関数を個別に呼ぶ |
| Player / Enemyの判別 | 仮想関数によって実体に応じて決まる | 呼び出す側が関数名を選ぶ |
| 処理手順 | `Actor::Update()` に共通化 | `main()` が順番を組み立てる |
| 新しいActorへの差し替え | 共通インターフェースを実装すればゲームループを再利用しやすい | 呼び出す関数や処理順の修正が必要になりやすい |
| 状態と処理 | Actorと派生クラスへまとめる | Actorの状態を外側の通常関数が操作する |

なお、じゃんけんの勝敗判定は登場人物固有の処理ではないため、両方とも `Janken::Judge()` に分離しています。オブジェクト指向だからといって、すべての処理を無理にクラスへ入れる必要はありません。

## Visual Studioで実行する

### 必要な環境

- Visual Studio 2022
- 「C++によるデスクトップ開発」ワークロード
- Windows 10 SDK

### ソリューションを開く

1. `Rock-paper-scissors.sln` をVisual Studioで開きます。
2. ソリューション エクスプローラーに2つのプロジェクトが表示されることを確認します。

### スタートアッププロジェクトを切り替える

実行したいプロジェクトを切り替えることで、2つの設計を同じ操作で比較できます。

1. ソリューション エクスプローラーで、実行したいプロジェクトを右クリックします。
2. **［スタートアップ プロジェクトに設定］**を選択します。
3. 次のどちらかを選びます。
   - `Rock-paper-scissors`：オブジェクト指向版
   - `Rock-paper-scissors-Procedural`：手続き型中心版
4. 選択したプロジェクト名が太字になったことを確認します。
5. `Ctrl + F5` で実行します。

片方を実行した後、もう片方をスタートアッププロジェクトに設定して再度実行してください。表示されるゲームは同じでも、内部で「誰が処理を選んでいるか」が異なることをソースコードで確認できます。

右クリックメニューが見つからない場合は、ソリューションのプロパティから**［共通プロパティ］→［スタートアップ プロジェクト］→［単一スタートアップ プロジェクト］**を選ぶ方法もあります。

## ゲームの操作

プレイヤーは次の数字を入力して手を選びます。

```text
0 : グー
1 : チョキ
2 : パー
```

負けた側のHPが1減り、どちらかのHPが0になるとゲーム終了です。

## 主なファイルの役割

```text
Rock-paper-scissors.sln
├─ Rock-paper-scissors/              オブジェクト指向版
│  ├─ Actor.*                        共通状態・共通処理・仮想関数
│  ├─ Player.*                       入力による手の選択
│  ├─ Enemy.*                        乱数による手の選択
│  ├─ Janken.*                       じゃんけんの勝敗判定
│  └─ Rock-paper-scissors.cpp        生成とゲームループ
└─ Rock-paper-scissors-Procedural/   手続き型中心版
   ├─ Actor.*                        状態と通常関数
   ├─ Player.*                       Playerと手選択関数
   ├─ Enemy.*                        Enemyと手選択関数
   ├─ Janken.*                       じゃんけんの勝敗判定
   └─ Rock-paper-scissors-Procedural.cpp
                                      処理の選択とゲームループ
```

## おすすめの学習手順

1. まず両方のプロジェクトを実行し、同じゲームであることを確認する
2. それぞれの `main()` を並べて、手を選ぶ処理の呼び出し方を比較する
3. オブジェクト指向版の `Actor::Update()` と `SelectHand()` を追う
4. `Player` と `Enemy` の `override` の違いを確認する
5. オブジェクト指向版の生成部分を `Enemy` 同士などに差し替え、ゲームループを変更せず動作することを試す
6. 同じ差し替えを手続き型中心版で行い、関数呼び出し側にも変更が必要になることを確認する

この比較を通して、構文を覚えるだけでなく、**変更が発生したときに、どの場所を修正する必要がある設計なのか**に注目してみてください。

## 教材上の補足

- 両方の `Actor` が持つ仮想デストラクタは、`Actor*` から派生オブジェクトを安全に `delete` するためのものです。手の選び方を切り替える仮想関数とは役割が異なります。
- `new` と `delete` は、2つの設計を同じ形で比較しやすくするために使用しています。実際の開発では、所有権を安全に管理するために `std::unique_ptr` などのRAIIも検討します。
- 「生成部分だけを差し替えられる」とは、`Actor` の契約を満たす派生クラスが用意されている場合の話です。新しいクラスそのものの実装が不要になるわけではありません。
